# @biatec/chat-protocol

Typed JSON contract between the Biatec Chat widget and the backend: session state, chat requests, suggestions,
action previews, consent status and the SSE event union. The types are **generated** from the backend's OpenAPI
document; do not edit `openapi.json` or `src/generated/` by hand.

## Where the contract lives

- C# DTOs: `backend/Biatec.Chat.Api/Contracts/`
- OpenAPI document: served at `/openapi/v1.json` when the backend runs in Development, and committed here as
  `openapi.json`
- TypeScript: `src/generated/schema.ts` (generated by `openapi-typescript`), re-exported with friendly names from
  `src/index.ts`

`ChatEvent` is a discriminated union on `type` (`text_delta`, `tool_status`, `preview_card`, `consent_status`,
`sign_in_card`, `error`):

```ts
import type { ChatEvent } from "@biatec/chat-protocol";

function render(e: ChatEvent) {
  switch (e.type) {
    case "text_delta": return e.text;
    case "error": return e.message;
    // ...
  }
}
```

## Regenerating

After changing anything under `backend/Biatec.Chat.Api/Contracts/`:

```sh
pnpm --filter chat-protocol generate   # needs the .NET 10 SDK
pnpm --filter chat-protocol build
```

`generate` builds the API project with `-p:OpenApiGenerateDocuments=true`, which writes `openapi.json` into this
directory, then runs `openapi-typescript` to produce `src/generated/schema.ts`. Commit both files. To regenerate only
the TypeScript from the committed document (no .NET needed): `pnpm --filter chat-protocol generate -- --skip-backend`.

If the backend gains a new event type, `src/index.ts` stops compiling until the new variant is added to `ChatEvent`.
Add a variant to a polymorphic C# type by adding a `[JsonDerivedType]` to `ChatEvent`.
